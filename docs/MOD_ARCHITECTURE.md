# Архитектура мода «Дети Эльтана»

## 1. Каноническая цель

«Дети Эльтана» — крупный мод для «Космических рейнджеров 2» / Space Rangers HD. Репозиторий должен описывать и собирать мод, а не собственный заменяющий движок.

## 2. Принцип адаптации

Любая идея из прежней KR3/WebGL-версии проходит через фильтр:

1. Уже есть в КР2 → используем базовую механику, меняем только данные/сценарий/баланс.
2. Поддерживается моддингом → реализуем нативно в моде.
3. Можно эмулировать через существующие механики → проектируем адаптацию.
4. Требует неподдерживаемого изменения движка → фиксируем как ограничение или экспериментальную ветвь, не блокируем основной мод.

## 3. Каноническая структура

`mod/` должен стать единственной релизной областью мода. Пока фактические форматы КР2 не подтверждены, структура остаётся нейтральной:

- `mod/manifest/` — версия, метаданные, совместимость;
- `mod/data/` — игровые таблицы и конфигурации;
- `mod/quests/` — квестовые пакеты и сценарии;
- `mod/text/` — оригинальные диалоги, описания и локализация;
- `mod/assets/` — только оригинальные или разрешённые ресурсы;
- `mod/scripts/` — скрипты/конвертеры, если формат моддинга требует их;
- `mod/tools/` — валидаторы и сборочные утилиты проекта.

Нельзя объявлять выдуманный формат «форматом КР2». Каталоги выше — организационный слой репозитория до подтверждения реальной схемы установки.

## 4. Legacy WebGL

`game/webgl/` сохраняется как исторический прототип. Его назначение теперь:

- источник уже реализованных дизайн-решений;
- песочница для проверки идей;
- референс чисел/баланса/UX;
- архив автономной реализации.

Новые задачи не должны автоматически расширять WebGL. Сначала нужно спросить: «Как эта механика должна жить внутри КР2?»

## 5. Карта переноса систем

### Использовать базовый КР2

Полёт, звездные системы, торговлю, посадки, оборудование, базовый бой, NPC-рейнджеров, интерфейс и другие зрелые системы следует переиспользовать, если моддинг позволяет менять необходимые данные.

### Переносить как контент

- сюжет «Детей Эльтана»;
- Махпеллы / Исказитель Реальности;
- новые цепочки заданий;
- новые NPC и тексты;
- репутационные последствия;
- стартовые архетипы рейнджера;
- новое оборудование и баланс;
- события, слухи, новости и описания;
- расширенный лор эпохи после КР2.

### Проверять на реализуемость

- глубокий гипер как отдельный слой мира;
- сложная Alliance Grid;
- многоуровневая динамическая война;
- новые глобальные правила дипломатии;
- нестандартные UI-сценарии;
- любые механики, требующие изменения бинарного движка.

## 6. Совместимость и исследование

Любая техническая реализация должна иметь ссылку на подтверждённый источник: документацию, известный mod kit, проверенный пример мода или воспроизводимый эксперимент. В `docs/` следует вести таблицу: возможность → источник → способ реализации → ограничения → тест.

## 7. CI и релизы

Целевой CI должен постепенно проверять:

- корректность структуры `mod/`;
- валидность JSON/YAML/текстовых исходников проекта;
- отсутствие запрещённых/неразрешённых бинарных ассетов;
- воспроизводимую сборку пакета мода;
- наличие manifest/version/changelog;
- smoke-проверки конвертеров и валидаторов.

WebGL build остаётся исторической проверкой только пока legacy-код активно поддерживается. Он не должен быть главным release gate для «Детей Эльтана».

## 8. Release definition

Релиз «Детей Эльтана» — это устанавливаемый пакет мода для поддерживаемой версии КР2 с инструкцией установки, changelog и подтверждённой совместимостью. WebGL ZIP/APK не считается основным релизом проекта.
