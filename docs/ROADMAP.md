# Roadmap — «Дети Эльтана» как мод для Космических Рейнджеров 2

> **Living roadmap.** Канонический shipping target — мод для КР2/SRHD. Старый WebGL runtime сохранён как legacy prototype и больше не определяет основной путь разработки.

## Current Direction

**Главная цель:** создать крупный сюжетно-системный мод **«Дети Эльтана»** поверх существующего движка Космических Рейнджеров 2 / Space Rangers HD, максимально переиспользуя уже готовые механики базовой игры и добавляя оригинальный контент через подтверждённые modding-механизмы.

**Каноническое начало кампании:** 1 января 3550 года, если выбранный формат мода позволяет корректно задать/обыграть дату.

**Приоритет разработки:**

`Modding capability audit → minimal installable mod → first original quest/content slice → campaign structure → systemic consequences → advanced custom mechanics only where technically supported`

## Phase M1 — Modding Capability Audit — CURRENT PRIMARY PHASE

Цель: не гадать, а точно установить, что можно модифицировать в целевой версии КР2/SRHD.

Нужно документально подтвердить:

- [ ] точную целевую версию/издание игры;
- [ ] структуру папок и способ загрузки модов;
- [ ] форматы игровых данных;
- [ ] формат и инструменты текстовых квестов;
- [ ] возможности событий/скриптов;
- [ ] добавление/изменение оборудования;
- [ ] работу с расами, репутацией, отношениями и генерацией контента;
- [ ] возможности изменения карты/систем/планет;
- [ ] возможности сюжетных цепочек и условий;
- [ ] возможности гипера/чёрных дыр/аркадных режимов;
- [ ] ограничения интерфейса;
- [ ] совместимость с популярными mod frameworks;
- [ ] требования к установке и упаковке;
- [ ] лицензии и условия использования нужных инструментов.

Результат фазы: `docs/MODDING_RESEARCH.md` + таблица `supported / tool-assisted / unverified / unsupported`.

## Phase M2 — Minimal Installable Mod

Цель: получить первый пакет, который реально устанавливается поверх КР2/SRHD и меняет ровно одну оригинальную вещь проекта.

- [ ] создать `mod/children_of_eltan/` или фактически требуемую toolchain-структуру;
- [ ] добавить manifest/metadata, если формат это поддерживает;
- [ ] добавить один оригинальный безопасный контентный элемент;
- [ ] написать reproducible build/package script;
- [ ] написать validation/smoke-check для структуры пакета;
- [ ] описать clean install / uninstall;
- [ ] не включать оригинальные защищённые файлы базовой игры.

## Phase M3 — First Children of Eltan Vertical Slice

Цель: впервые показать саму новую кампанию внутри настоящего gameplay-loop КР2.

Предпочтительный состав:

- [ ] стартовая сюжетная завязка «Детей Эльтана»;
- [ ] один полноценный текстовый квест или цепочка событий;
- [ ] один новый персонаж/контакт;
- [ ] одна оригинальная награда/оборудование/доступный контент;
- [ ] хотя бы одно последствие выбора игрока;
- [ ] интеграция с существующей торговлей/боем/репутацией КР2 вместо собственной копии этих систем.

## Phase M4 — Campaign Foundation

- [ ] канонизировать 3550 год и состояние галактики;
- [ ] Махпеллы и «Исказитель Реальности» как центральная угроза;
- [ ] ранние следы Келлера;
- [ ] древнее гаальское пророчество;
- [ ] первые гибридные цивилизации;
- [ ] сюжетные развилки между обычным sandbox и основной кампанией;
- [ ] 5–10 крупных авторских квестов;
- [ ] повторяемые системные события, если modding API это позволяет.

## Phase M5 — Systemic Expansion

В этой фазе реализуются только механики, подтверждённые M1-аудитом.

Кандидаты:

- Smart Diplomacy поверх существующей репутации/квестовых условий;
- Alliance Grid в форме, доступной моддингу;
- расширенные фракционные последствия;
- новые типы контрактов;
- новые предметы/оборудование;
- редкие технологии и артефакты;
- новые encounter/event chains;
- черный рынок/контрабанда;
- дополнительные NPC-роли;
- новые планетарные/станционные тексты и события;
- сюжетно значимые войны и изменения состояния галактики.

Если конкретная идея требует переписывания движка с нуля и не поддерживается modding path, она либо адаптируется, либо переносится в отдельный research backlog.

## Legacy WebGL Track

`game/webgl/` не удаляется, но новые задачи туда попадают только если они:

- помогают проверить дизайн будущей mod-механики;
- нужны для извлечения/документирования уже созданной логики;
- являются небольшим preservation fix.

Standalone WebGL/APK релизы больше не являются roadmap milestone проекта.

## Interpretation of old parity documents

`KR2_MECHANICS_PARITY_MATRIX.md` и `KR2_EXHAUSTIVE_FEATURE_AUDIT.md` теперь читаются иначе:

- если КР2 уже имеет механику — **reuse**;
- если моддинг позволяет расширить механику — **extend**;
- если возможность не подтверждена — **research**;
- если невозможно — **adapt design**;
- не переписывать базовую игру ради галочки parity.

## Agent Coordination Protocol

Перед выбором задачи агент обязан:

1. получить свежий `master`;
2. прочитать `README.md`;
3. прочитать `docs/MOD_ARCHITECTURE.md`;
4. проверить этот roadmap;
5. проверить последние коммиты;
6. изучить подтверждённые modding-возможности;
7. выбрать ровно один небольшой mod-first инкремент.

Не добавлять standalone-фичу в WebGL как замену отсутствующей mod-фичи без явного решения проекта.

## Definition of Done

Пункт mod-roadmap считается завершённым, только если:

- изменение присутствует в фактическом mod source/package;
- формат проверен соответствующим инструментом или валидатором;
- заявленная совместимость подтверждена для целевой версии игры;
- установка не требует коммита защищённых файлов базовой игры;
- документация честно описывает уровень runtime-проверки;
- legacy WebGL prototype сам по себе не считается доказательством реализации в моде.
